# Web制作基礎 第一回：逻辑检查与修改

采用共享对话中最新版的52页师生共用课件，保留KCG模板和原有课程边界。第一回不教HTML标签输入，第二回才开始写见出し和文章。

## 整体判断

原课件的主线合理：先看做得出的成品，理解为什么需要Web，再看网页如何显示，区分HTML与CSS，最后安装工具并练习文件操作。主要问题是旧案例、截图和实际网站不同，个别过渡与当前部署状态不一致。

## 修改后的顺序

| 页码 | 学生要理解或完成什么 | 接到下一段的理由 |
|---|---|---|
| P01–P11 | 看清水寺网站、了解15回目标、观察页面 | 知道成品之后，再理解它的来历 |
| P12–P19 | 从资料分享理解网络、互联网和Web | 接着看自己打开网页时会发生什么 |
| P20–P26 | 页面、网站、链接、URL、浏览器、服务器、文件 | 明确网页由哪些材料组成 |
| P27–P35 | 通过同一案例的对照图区分HTML与CSS | 先分清工作，再准备写文件的工具 |
| P36–P45 | 区分语言和应用，理解本地与公开，安装并重开VS Code | 道具准备好后练习基本操作 |
| P46–P52 | 打开文件夹，编辑、保存、关闭、重开memo.txt | 第二回复用相同操作开始写HTML |

## 已修正的问题

1. P03–P06、P11、P20、P27–P33统一使用“京都さんぽ・清水寺”，替换旧图书馆、公园、学习场所案例及截图。
2. P18原本提前承诺紧接着讲HTML/CSS，现在先接“网页如何到达屏幕”，再接材料分工。
3. P22的URL改成刚刚观察过的清水寺页面，避免突然跳到VS Code下载页；安装入口仍保留在P41。
4. P27–P33每次只改变一个条件：文章内容、CSS有无、颜色或间距；明确“没有作者CSS”仍可按浏览器默认样式显示。
5. P37改成已公开的真实情况，同时说明保存到本机与网络公开的区别。P11/P22加入可点击的实际网址。
6. P06按真实手机布局说明目次从左侧移到上方。P07说明最低目标是连接两页以上，与三页示例并不冲突。
7. 课件正文和图中日文保持短句，修正生硬表达；以清晰说明为主，不加入营销式口号。

## 180分钟的使用建议

| 净授课时间 | 内容 |
|---|---|
| 0–15分钟 | P01–P10：介绍成品与课程目标 |
| 15–25分钟 | P11：学生观察网站，10分钟 |
| 25–60分钟 | P12–P33：发展缘由、显示过程、HTML/CSS对照 |
| 60–76分钟 | P34：学生分类与指图，16分钟 |
| 76–90分钟 | P35–P41：核对答案与工具准备 |
| 90–100分钟 | P42–P50：辨认系统、示范操作路线 |
| 100–175分钟 | 学生安装、保存、重开并验证，75分钟；教师巡回 |
| 175–180分钟 | P51–P52：学生展示结果并接到下一回 |

学生观察、分类、操作和展示共计划106分钟。下载等待不能代替练习，等待时继续前面的观察与分类。历史部分不要求记年号。根据学生日语程度放慢时，减少重复口述，优先保留动手时间。
